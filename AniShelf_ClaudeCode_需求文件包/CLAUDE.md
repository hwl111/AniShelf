# AniShelf 项目开发规则

## 1. 项目目标

AniShelf 是 Windows 优先的个人桌面知识管理应用，将番剧管理、本地电子书阅读和知识笔记整合在一个本地优先的软件中。

V1.0 核心闭环：
- 番剧：添加作品 → 管理观看状态/集数 → 记录观看历史 → 写单集感想。
- 阅读：导入书籍 → 阅读 → 添加书签/批注 → 自动保存阅读进度 → 恢复上次位置。
- 知识：创建笔记 → 关联番剧/书籍/批注 → 双向链接 → 全局搜索。

## 2. 技术栈基线

- 桌面框架：Tauri 2
- 前端：React + TypeScript + Vite
- UI：Tailwind CSS + shadcn/ui，默认深色主题
- 状态：Zustand
- 服务端状态/异步请求：TanStack Query
- 后端：Rust
- 数据库：SQLite，通过 SQLx 或经过评估的等价方案
- EPUB：epub.js
- PDF：PDF.js
- TXT：Rust 后端分块读取，前端分页/虚拟列表
- Markdown：成熟 Markdown parser，支持预览与编辑
- 番剧元数据：Bangumi API，可手动添加，不强制联网

如需更换关键技术，先说明原因、影响和迁移成本，等待用户确认。

## 3. 开发原则

1. Windows 原生开发优先；不要默认引入 WSL。
2. 本地优先：用户资料和书籍内容默认保存在本机。
3. 离线可用：手动添加、阅读、笔记等核心功能不依赖 Bangumi 或 AI 服务。
4. 数据安全优先：数据库迁移前备份；禁止未经确认删除或覆盖用户数据。
5. 原始书籍文件默认只读，不直接修改用户原文件。
6. Bangumi 同步只更新外部元数据，不覆盖用户自己的评分、进度、笔记、观看记录等个人数据。
7. 组件和业务模块按 feature 拆分，避免把所有逻辑堆进单一页面或组件。
8. 所有重要业务逻辑放在可测试的 service/repository 层。
9. 错误需要给用户可理解的提示，同时记录必要日志；不得静默吞掉错误。
10. 不要为了“看起来完成”而写假数据、空实现或绕过验收测试。

## 4. 安全与权限

- 执行安装器、管理员命令、修改 PATH/注册表/系统设置前，先解释并征求确认。
- 执行删除、批量覆盖、数据库重置、清理目录等不可逆操作前，必须确认。
- 不得擅自执行 `git reset --hard`、`git clean -fdx`、删除用户目录或覆盖已有项目。
- 导入文件时验证扩展名、文件大小、路径和实际文件类型。
- EPUB/ZIP 解包必须防止 Zip Slip 路径穿越。
- 不自动执行导入内容，不自动加载书籍中的外部脚本。
- PDF/EPUB 外部链接默认不自动打开，需用户主动操作。
- 不将 API Token、密钥、个人文件路径或个人数据写入 Git。
- 对 Tauri command 做参数校验，不信任前端传入的路径。

## 5. 数据库规则

- SQLite 连接必须启用 `foreign_keys`。
- 合理配置 WAL、busy_timeout。
- Migration 必须可重复验证、按版本执行，并尽量事务化。
- 数据库结构变化必须新增 migration，不得随意修改已经发布的旧 migration。
- 多态关联表的目标实体存在性由 Service 层校验。
- FTS 索引必须具备插入、更新、删除同步机制。
- 中文全文搜索方案必须通过实际测试验证；不要假设 SQLite 默认 FTS tokenizer 能提供理想中文分词。
- 为关键表添加必要索引、唯一约束和时间戳字段。

## 6. 工程质量

- TypeScript 开启严格模式。
- Rust 代码格式化并通过 `cargo check`。
- 前端通过 lint、typecheck、build。
- 核心 service/repository 有单元测试。
- 关键流程有集成测试或手动验收步骤。
- 不允许把所有错误都用 `any`、`unwrap()` 或空 catch 处理。
- 每个阶段结束时输出：完成内容、修改文件、执行的命令、测试结果、已知问题、下一步建议。

## 7. Git 约定

- 初始化 Git；建立合理 `.gitignore`。
- 不提交 `node_modules`、`target`、构建产物、数据库运行数据、用户书籍、密钥和 IDE 缓存。
- 每个开发阶段建议独立 commit。
- 提交前检查 `git status` 和 diff。
